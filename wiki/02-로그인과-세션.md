# 2. 로그인 서버와 세션

[1장](01-환경과-HTTP.md)의 서버를 실행한다. 단일 가상 사용자의 공유 암호 방식이며 회원가입 서비스나 Google 로그인의 대체품이 아니다.

| 요청 | 입력 | 결과 |
|---|---|---|
| POST /lab/login | JSON password | token, expires_in=300 또는 401 |
| GET /lab/session | Authorization: Bearer 토큰 | authenticated, 200/401 |
| POST /lab/logout | 같은 Authorization | 토큰 제거 |

## 구현 원리

로그인 시 secrets.token_urlsafe로 새 토큰을 만들고 메모리에 만료시각과 함께 보관한다. time.monotonic은 시스템 시각 보정에 영향받지 않는 대기 기준이다. 서버 재시작으로 세션은 사라진다. 여러 HTTP 스레드가 공유하므로 잠금 안에서 세션을 검사·삭제한다.

만료 정리와 최대 100개 제한이 있지만 사용자별 로그인 시도 제한이나 인터넷 공격 방어를 구현한 서버는 아니다. 공개 런처의 로컬 기능에는 이 로그인이 필요하지 않다.

## 로그아웃 검증

서버 실행 중 둘째 터미널에서 실행한다. 토큰을 출력하지 않는다.

```powershell
@'
import os, requests
base = 'http://127.0.0.1:8000'
s = requests.Session()
r = s.post(base+'/lab/login', json={'password':os.environ['LAB_PASSWORD']}, timeout=5)
r.raise_for_status()
s.headers['Authorization'] = 'Bearer '+r.json()['token']
print(s.get(base+'/lab/session', timeout=5).status_code)
print(s.post(base+'/lab/logout', timeout=5).status_code)
print(s.get(base+'/lab/session', timeout=5).status_code)
'@ | & $python -
```

예상 결과는 200, 200, 401이다. 만료는 5분 대기하거나 자동 테스트의 가상 만료값으로 검증한다. 제품 서버의 시간을 변경하지 않는다.

## Google 인증으로 확장하기

[oauth_desktop.py](../examples/oauth_desktop.py)는 PKCE/state 생성과 코드 교환 함수까지 제공한다. 다음은 자신의 OAuth 앱에서 구현할 확장 절차다.

1. [API 설정](API_SETUP.md)에 따라 자신의 데스크톱 클라이언트를 등록한다.
2. 시스템 브라우저를 열기 전에 루프백 콜백 수신기를 준비한다.
3. 요청마다 state/verifier를 메모리에 보관한다. redirect_uri는 요청과 코드 교환에서 같아야 한다.
4. 콜백의 오류·시간초과·state 불일치를 먼저 처리한다. 인증 코드와 전체 URL을 로그로 남기지 않는다.
5. code를 verifier와 함께 교환한다.
6. 서버에서 검증된 라이브러리로 ID 토큰의 서명·iss·aud·exp를 검증한다. 사용자 식별에는 안정적인 sub를 사용한다.
7. 검증 후 앱 세션을 별도로 발급한다. 공급자 토큰과 앱 세션을 혼용하지 않는다.

데스크톱에 포함된 client secret은 배포 후 숨길 수 있는 서버 비밀이 아니다. JWT 디코딩만으로 로그인 성공을 판정하지 않는다. [Google 데스크톱 OAuth](https://developers.google.com/identity/protocols/oauth2/native-app), [서버 ID 토큰 검증](https://developers.google.com/identity/sign-in/web/backend-auth)

연습: 세션을 DB에 저장한다면 원문 대신 토큰 해시, 만료·폐기를 설계한다. 회원 비밀번호는 전용 비밀번호 해싱을 사용한다. 교재의 공유 암호를 회원 DB 저장 방식으로 옮기지 않는다.
