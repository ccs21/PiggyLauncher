# 6. 백업·복원과 운영 전환

## 가상 DB 백업 실습

3장의 가상 DB만 사용한다.

```powershell
& $python examples/notice_store.py --backup lab_data/notices-copy.sqlite
& $python examples/notice_store.py --db lab_data/notices-copy.sqlite --list
```

순번·내용을 원본과 비교한다. SQLite backup API로 사본을 만들며 기존 목적 파일은 덮어쓰지 않는다. 다시 실행할 때는 새 이름을 사용한다. 복원 연습은 원본을 바꾸지 않고 LAB_NOTICE_DB를 사본 경로로 설정해 서버를 시작한다. 각각에 공지를 추가해 독립적으로 유지되는지 확인한다.

## 외부 공개에서는 달라지는 것

내장 http.server는 로컬 학습용이다. 인터넷에는 운영용 앱 서버와 인증·요청 제한을 준비하고 역방향 프록시가 HTTPS를 담당하게 한다. 로그에 비밀번호·토큰·본문을 남기지 않는다. 데이터·비밀 설정의 파일 권한은 서비스 계정으로 제한한다.

자신의 도메인과 운영용 앱이 준비된 경우 Caddy 개념 설정은 다음과 같다. 교재 서버를 그대로 공개하라는 명령이 아니다.

```caddyfile
launcher.example.com {
    reverse_proxy 127.0.0.1:9000
}
```

실제 소유 도메인, DNS, 방화벽·포트, 영속 인증서 저장소가 필요하다. 예제 도메인으로 인증서를 발급받지 않는다. [Caddy 자동 HTTPS 문서](https://caddyserver.com/docs/automatic-https)

## 배포 절차

1. 가상 사용자·데이터로 앱과 실패 경로를 검증한다.
2. 일반 권한 서비스 계정과 전용 데이터 디렉터리를 만든다.
3. 환경변수/비밀 저장소를 구성하고 Git에서 제외한다.
4. 앱 포트는 루프백으로 제한하고 프록시만 노출한다.
5. 요청 크기·시간·로그인 빈도 제한과 관리자 권한 검사를 추가한다.
6. DB 변경 전 백업을 만들고 별도 사본에 복원해 검증한다.
7. 상태 확인·오류 관찰·이전 버전 복구 절차를 준비한다.

로그는 상태 코드·처리 시간·임의 요청 ID부터 시작한다. 개발 편의용 TLS 검증 해제 옵션을 운영에 옮기지 않는다.

Google 검증 라이브러리 연결, 실제 회원 저장, 관리자 웹 UI, 세션 갱신, 공격 방어, 운영 자동화는 요구에 따라 직접 구현할 과제다. 이 교재는 실행 가능한 로컬 로그인·공지·백업 예제와 운영 전환 설명을 제공하며 상용 인증 서버 완제품은 제공하지 않는다.
