# 5. Qt와 백그라운드 작업

서비스 어댑터는 HTTP/JSON 변환, 작업 스레드는 조회 순서, GUI는 표시와 입력을 담당한다. 예제 서버는 독립 실행이다. 공개 런처는 시작 시 교재 서버나 로그인 서버에 자동 연결하지 않는다.

```text
온라인 전환 → 공지 페이지 수신·저장 → 업데이트 조회 → 세션 확인
게임 시작 → 취소 요청 → 현재 요청 반환 → 다음 단계 진입 금지
게임 종료 → 새 작업 세대 생성 → 저장 커서부터 재개 → 알림 큐 표시
```

## 이미 있는 코드에서 배우기

[register_thread.py](../register_thread.py)는 I/O 결과를 progress 신호로 보낸다. worker에서 위젯을 직접 변경하지 않는다. [game_detail_screen.py](../game_detail_screen.py)의 restore_requested는 QueuedConnection으로 GUI 슬롯에 연결한다.

quit()은 Python 반복문을 중단하지 않는다. requestInterruption과 isInterruptionRequested를 작업 경계에서 사용한다. 시작된 requests 호출은 timeout까지 기다릴 수 있으므로 반환 후에도 취소를 확인한다. GUI에서 wait로 기다리면 취소 화면까지 멈출 수 있다.

동기화마다 generation 정수를 부여하면 이전 작업의 늦은 응답을 버릴 수 있다. 응답 세대가 현재 세대와 다르면 화면에 적용하지 않는다. 실행 중인 QThread는 삭제하지 않고 finished 후 해제한다.

## 공지 연결 절차

1. worker에서 notice_sync의 페이지를 조회한다.
2. 커서와 미표시 항목을 함께 저장한다.
3. GUI 시그널로 표시 요청을 전달한다.
4. 게임 중이면 표시만 보류하고 항목을 지우지 않는다.
5. 실제 표시 후 확인 처리한다.

인터넷 연결·이번 검증 결과·마지막 정상 로그인 상태를 분리한다. timeout만으로 로그아웃을 확정하면 오프라인 사용 경험이 나빠진다.

실험: 가짜 응답을 지연시키고 창 닫기와 게임 시작을 발생시킨다. 늦은 응답이 창을 다시 열지 않는지, 두 작업이 같은 파일을 쓰지 않는지 확인한다. tests/test_review_regressions.py의 GUI 복귀와 이전 sender 무시 테스트부터 읽는다.
