# 학습용 코드 정리 원칙

## 보존할 것

프로그램의 주요 기능과 실제 문제를 해결하려던 의도를 보존한다. 교육용이라는 이유로 실행·종료 판정이나 저장 형식을 근거 없이 단순화하지 않는다. 수정 전후의 동작을 확인하고, 공개본에서 의도적으로 달라진 부분은 기록한다.

## 제거할 것

광고, 후원, 회원 등급 제한, 운영 서비스 연결, 비밀정보, 개인 데이터, 참조되지 않는 백업 코드를 제거한다. 프리미엄 값을 항상 참으로 만드는 방식 대신 등급 검사와 잠금 화면 자체를 정리한다. 독립적인 서버 실습은 런처의 기본 사용 조건으로 만들지 않는다.

## 주석의 역할

- 모듈 첫머리: 담당 기능과 다른 모듈과의 경계.
- 중요한 함수: 입력·반환값·파일/프로세스/UI에 미치는 영향.
- 스레드와 Qt: 어느 스레드에서 실행하며 화면 변경을 어떻게 전달하는지.
- 우회 구현: 필요한 이유, 재현 조건, 해결하지 못하는 경우.
- 피할 주석: 코드와 다른 과거 설명, 근거 없는 성능 수치, 단순 문법 번역, 완료되지 않은 기능을 완료했다고 적는 설명.

예를 들어 `sleep(3)`에 “3초 대기”라고만 적기보다 무엇을 기다리는지, 왜 확실한 완료 신호를 사용하지 못했는지, 기기 성능이 달라지면 무엇이 문제인지 설명한다. 이유를 확인하지 못했다면 추측으로 채우지 않는다.

## 사실과 해석 구분

- **코드에서 확인:** 파일·함수와 실제 제어 흐름으로 설명.
- **개발자 경험:** 개발자가 제공한 당시 상황임을 명시.
- **개선 과제:** 아직 반영하지 않은 대안과 검증 방법으로 제시.

GPT-6을 이용한 정리·주석 추가 사실을 README에 명시한다. 원래 개발 과정과 이번 편집 작업을 구분한다. AI 이용 여부에 대한 평가보다 독자가 구현을 읽고 검증하도록 돕는 데 집중한다.

## 완료 기준

각 묶음은 참조 확인 → 민감정보 제거 → 코드 정리 → 의미 있는 검증 → 설명 작성 순으로 진행한다. 최종 공개 전에는 실행 가능 여부, 의존성, 리소스 재배포 조건, 문서와 실제 코드의 일치를 확인한다. 공개 후 유지보수는 예정하지 않는다.
