# 공개본 함수·상태 흐름 검수

2026-10-09, 공개용 소스만 대상으로 수행했다. Classic 원본과 2.0, 운영 서버는 수정하지 않았다.

## 어떻게 조사했는가

모든 Python 파일을 AST로 읽어 함수·중첩 함수·메서드를 목록화했다. 이름/속성/문자열 참조와 import, Qt 콜백을 대조했다. 같은 스코프에서 함수를 덮어쓰는 중복 정의와 return/raise 뒤 명백한 도달 불가 문장도 확인했다. 전체 결과는 [함수별 읽기 색인](FUNCTION_INDEX.md)에 있다.

정적 분석은 동적 호출을 완전히 해석하지 못한다. 따라서 이름이 안 보인다는 이유만으로 `run`, `closeEvent`, HTTP 핸들러, 테스트 함수를 제거하지 않았다. 반대로 같은 이름의 메서드가 다른 클래스에서 사용되면 참조가 있는 것으로 집계될 수 있다. 이 색인은 실행 검증을 대체하지 않는다.

## 제거한 함수 블록

다음 18개 함수는 공개본의 실행 코드·문자열 콜백 연결을 대조한 뒤 제거했다. 함수 내부의 중첩 함수도 함께 제거되었다.

| 파일 | 제거 함수 | 이유 |
|---|---|---|
| bottom_bar.py | `_create_icon_button`, `update_button_style`, `simulate_key` | 현재 버튼 구성과 연결되지 않은 보조 경로 |
| cdp_dom_scraper_steam.py | `get_main_launcher` | 수집 흐름에서 호출되지 않는 창 탐색 |
| cdp_register_common.py | `wait_for_login_ready`, `find_tab` | 사용하지 않는 로그인 대기 경로 및 전용 보조 함수 |
| central_content.py | `wrap_card_click`, `add_game` | 현재 카드 이벤트·파일 재조회 경로와 중복되는 미연결 구현 |
| gamepad_manager.py | `get_connected_gamepad_guids` | 현재 신규 패드 검색에서 사용하지 않음 |
| game_detail_screen.py | `has_window_with_title` | 실제 감시는 다른 창 판별 함수를 사용 |
| main.py | `regain_focus_and_foreground` | 현재 복귀 경로에서 호출되지 않음 |
| sdl_gcdb.py | `pick_best` | 실제 호출은 이유까지 반환하는 `pick_best_with_reason` |
| settings_popup.py | `move_to_parent_center` | 창 배치에 연결되지 않음 |
| steam_scanner.py | `find_exe_full_path` | 설치 검색의 현재 실행 파일 탐색 경로에서 사용하지 않음 |
| top_bar.py | `get_network_info` | 제거된 광고 모듈용 보조 API |
| user_register_popup.py | `on_search_ready`, `create_section_with_buttons` | 현재 검색 콜백과 레이아웃 생성에 연결되지 않음 |
| auto_register_popup.py | `debug_top_windows` | 출력 제거 후 아무 효과 없는 창 열거만 남았음 |

이전 출력문 제거 뒤 남은 빈 조건문·빈 반복문·사용하지 않는 조회식도 정리했다. 예외 처리에서 의도적으로 무시하는 `pass`와 Qt가 호출하는 메서드는 남겼다. `rom_list_core_cleaner._log`는 빈 함수로 두지 않고 로컬 DEBUG 로깅에 연결했다.

| 프리셋 중간 실패 후 일부 설정만 변경된 상태로 잔류 | 변경 전 기록, 실패 시 복구, 실패 결과 반환 | 볼륨 실패 후 해상도 롤백 테스트 |

| 등록 스레드의 인증 알림/종료 신호가 새 작업을 교차 처리 | 스레드 `finished` 후에만 인증 재시도 예약 | 이전 sender가 새 작업을 진행하지 않는 테스트 |
| 수집기 예외 한 건이 전체 등록을 중단 | 게임별 실패 격리, 결과 누적 | 첫 항목 예외 후 다음 항목 성공 테스트 |

| 자동등록 창 닫기에서 GUI가 무기한 `wait` | 작업 중단 요청 후 종료 신호에서 닫기 | 호출 경로 검토; 실제 HTTP 종료 지연은 미검증 |
| ROM 수집이 `QThread.finished`를 다시 정의·직접 발생 | QThread 기본 완료 신호 사용 | 코드 대조; 실제 서비스 호출 미수행 |

| 수동등록 필드가 위젯 생성 순서의 숫자 인덱스에 의존 | title/developer/publisher/release_date 키로 참조 | 소스 대조 및 폼 회귀 테스트 |

## 주석 읽는 순서

1. `main.py` → `central_content.py`: 모델 읽기, 선택 식별자, 렌더 요청 합치기, 이미지 캐시.
2. `auto_register_popup.py` → `register_thread.py`: UI와 작업 스레드, 한 작업의 완료와 다음 작업의 시작.
3. `game_detail_screen.py` → `system_config_handler.py`: 시작 판정과 종료 판정 분리, 변경 전 기록과 복구.
4. `rom_list_popup.py` → `emulator_launcher.py`: ROM별 설정 우선순위, 가상 목록, 임시 배치·작업 폴더.
5. `scraper_setting_popup.py` → `cdp_register_common.py`: 키/옵션/진행 신호, 네트워크 대기와 자원 정리.
6. `notification_manager.py` → `notification_popup.py`: 큐 소유권과 실제 화면 완료 사건.

주석은 각 문장을 한국어로 번역하는 대신 **왜 그 순서인지, 누가 상태를 소유하는지, 실패하면 무엇이 남는지**를 설명한다. 함수 설명 95개를 추가한 뒤 결함 수정 함수에도 별도 설명을 보완했다. Qt 콜백과 짧은 UI 조립 코드는 상위 함수 설명 및 색인과 함께 읽는다.

## 유지한 한계와 후속 학습 과제

- 기존 모듈의 긴 UI/등록 함수와 광범위한 예외 처리가 모두 분해된 것은 아니다. 화면·파일 저장·서비스 어댑터를 나누는 리팩터링 과제로 삼을 수 있다.
- 일부 설치 검색과 외부 도구 호출은 동기식이다. 타임아웃이 있더라도 GUI에서 호출하면 그동안 지연될 수 있다.
- Classic의 프로세스 이름·시간 기반 시작/종료 정책과 스토어 DOM 의존성을 보존했다. 실게임 모든 조합의 동작을 보증하지 않는다.
- 등록 중단은 진행 중인 수집기 호출을 강제로 죽이지 않는다. 해당 호출이 끝나면 다음 게임을 시작하지 않는다. 수집기 전체에 취소 토큰을 전파하는 것은 별도 과제다.
- 파일 변경 여러 건을 하나의 트랜잭션으로 묶지는 않았다. 임시 파일 교체는 단일 파일 손상을 줄이며, 전원 차단 시 전체 작업 원자성을 보장하지 않는다.
- 실제 코어 DLL 실행, 로그인, 원격 스크래핑, 모니터/볼륨 변경은 이번 테스트에서 수행하지 않았다. 테스트는 임시 폴더와 가짜 응답/장치 어댑터를 사용한다.

의존성·라이선스 검토 결과와 빌드 등 검증 범위는 [검사 결과](REVIEW_RESULTS.md)를 참고한다.
